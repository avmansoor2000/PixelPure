# PixelPure — AI Watermark Remover & Image Enhancer

A full-stack SaaS-style web app for removing watermarks/unwanted objects (AI inpainting) and enhancing images (AI 2×/4× upscaling, denoise, light & clarity). Node.js + Express backend, dependency-free ES-module frontend.

## Quick start

```bash
npm install
cp .env.example .env        # add at least one AI provider key
npm start                   # http://localhost:3000
```

Requires Node 20+. Docker: `docker build -t pixelpure . && docker run -p 3000:3000 --env-file .env pixelpure`

## AI providers

All processing runs server-side; keys live only in `.env` and are never sent to the browser.

| Provider | Remove watermark | Enhance / upscale | Key |
|---|---|---|---|
| **Stability AI** | `v2beta/stable-image/edit/erase` | `upscale/fast` (≤1 MP, 4×) or `upscale/conservative` (larger) | `STABILITY_API_KEY` |
| **Clipdrop** | `cleanup/v1` (quality mode) | `image-upscaling/v1/upscale` (≤4096 px) | `CLIPDROP_API_KEY` |
| **Replicate** | LaMa (`allenhooo/lama`) | Real-ESRGAN (`nightmareai/real-esrgan`) | `REPLICATE_API_TOKEN` |
| Local (fallback) | Classical push-pull + harmonic fill — **not AI** | Lanczos + median denoise + unsharp — **not AI** | none |

`INPAINT_PROVIDER` / `ENHANCE_PROVIDER` = `auto` picks the first configured AI provider (Stability → Clipdrop → Replicate). You can mix them, e.g. Clipdrop for removal and Replicate for upscaling.

With no key the app still works using the local engine, and the editor clearly shows **"Local engine · non-AI"** so results are never passed off as AI. Set `ALLOW_LOCAL_FALLBACK=false` in production to refuse instead.

**Adding a provider:** create `server/providers/<name>.js` exporting `{ name, label, isAI, capabilities, isConfigured(), inpaint(), enhance() }` and register it in `server/providers/index.js`.

## How processing works

- **Upload** — multer (memory) → MIME filter → decoded by sharp (real format check, pixel limit, animated rejected) → EXIF-rotated, metadata stripped, stored as lossless PNG.
- **Remove** — the browser sends only the painted mask. The server binarises and slightly dilates it, the provider inpaints, and the result is blended back with a feathered mask so **every pixel outside the selection is unchanged**. Images larger than a provider's limit are downscaled for the call, and only the masked area is taken from the result.
- **Enhance** — target = size × 2 or 4 (capped at `OUTPUT_MAX_SIDE` / `OUTPUT_MAX_MEGAPIXELS`), provider upscale → exact Lanczos resize → optional auto-levels + CLAHE.
- **Export** — PNG (lossless) or JPG (mozjpeg, 4:4:4, q95).
- **Storage** — files expire after `FILE_TTL_MINUTES` (default 60); a sweeper deletes them every `CLEANUP_INTERVAL_MINUTES`. Users can delete earlier from the tray.

## Security

Helmet with strict CSP (no inline scripts/styles), per-IP rate limits on upload and processing, 128-bit random IDs validated by regex (no path traversal), file size/count/pixel limits, concurrency cap for heavy jobs, upstream errors mapped to friendly messages without leaking keys or vendor responses.

## API

| Method | Path | Notes |
|---|---|---|
| GET | `/api/config` | limits + active providers |
| POST | `/api/images` | multipart `images` (1–10 files) |
| POST | `/api/images/:id/inpaint` | multipart `mask` (PNG; painted = remove) |
| POST | `/api/images/:id/enhance` | JSON `{ scale: 2|4, denoise, autoLight }` |
| GET | `/api/images/:id` · `/thumb` · `/info` | full PNG, WebP thumbnail, metadata |
| GET | `/api/images/:id/download?format=png|jpg` | attachment |
| DELETE | `/api/images/:id` | early delete |

## Before going live

- Add your provider key(s), set `PUBLIC_URL`, `TRUST_PROXY=true` behind a proxy, and `ALLOW_LOCAL_FALLBACK=false`.
- Run `npm run samples` with your AI key set to regenerate the landing-page before/after images with AI output (the shipped samples were made by the local engine).
- Pricing plans are presentation only: Pro/Premium buttons go to the contact page. Plan quotas, accounts and payments (e.g. Stripe) are not implemented.
- Update the contact email in `scripts/build-pages.js` and legal copy to your business details.
- Storage is local disk; for multiple instances, swap `server/services/storage.js` for S3/R2 with lifecycle rules.
